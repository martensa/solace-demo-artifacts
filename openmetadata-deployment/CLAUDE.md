# CLAUDE.md -- OpenMetadata Deployment

## Overview

Helm-based deployment of OpenMetadata 1.6.x on Kubernetes. Standalone --
does NOT depend on the event-mesh-deployment. The Solace Event Portal
connector (in the sibling `om-connector/` project) plugs in afterwards.

## Cluster Dependencies

This deployment assumes the same cluster state as the other deployments
in this repo, provisioned by
[`solace-lab-infrastructure`](https://github.com/martensa/solace-lab-infrastructure):

- NGINX Ingress Controller (namespace `ingress-nginx`)
- cert-manager + ClusterIssuer `solace-lab-ca-issuer`
- trust-manager + ConfigMap `solace-lab-ca-trust-bundle` with the
  Kyverno policy `inject-solace-lab-ca-trust-bundle` that injects the
  lab CA + `SSL_CERT_FILE` / `REQUESTS_CA_BUNDLE` into every pod
- Kyverno policy `inject-registry-pull-secret` (only relevant once
  images are pulled from `registry.solace.lab`)

`start.sh` adds `openmetadata.solace.lab` to CoreDNS NodeHosts during
deployment; `stop.sh` removes it. Same decentralized hostname pattern as
`agent-mesh-deployment`.

Do not re-create the cluster-level resources from this repo.

## Start and Stop

```bash
./scripts/start.sh   # helm install both charts
./scripts/stop.sh    # full teardown incl. PVCs
```

## Helm Conventions

- Two charts from the `open-metadata` Helm repo:
  - `openmetadata-dependencies` (PostgreSQL + OpenSearch + Airflow)
  - `openmetadata` (server)
- Release names hardcoded in `start.sh`:
  - `openmetadata-dependencies`
  - `openmetadata`
- Namespace hardcoded: `openmetadata-solace-lab`.
- Both `values.yaml` files are checked in; they contain demo-only
  passwords and are intentionally non-secret. Production secrets would
  move to a Secret reference (`existingSecret:` etc.) -- not done here.

## Auth

Initial deployment uses **basic auth + JWT** with self-signup enabled.
The first user signing up with email `admin@open-metadata.org` becomes
admin. To swap to Keycloak OIDC later, add a Keycloak client setup
script (analog to `agent-mesh-deployment/scripts/setup-keycloak-client.sh`)
and flip `openmetadata.config.authentication.provider` to `oidc`.

## JWT Keys

RSA-2048 keypair generated by `scripts/setup-rsa-keys.sh` and stored in
the `openmetadata-jwt-keys` Secret. The server mounts them at
`/etc/openmetadata/jwtkeys/{public,private}_key.der`. **Do not rotate
without invalidating every previously issued ingestion-bot JWT.**

## Secrets Handling

This MVP has no real secrets in `.env` -- `.env.example` is checked in as
a placeholder for future values (`SOLACE_EVENTPORTAL_TOKEN`,
`OM_INGESTION_BOT_TOKEN`) used by the connector / bridge, not by the
deployment scripts themselves.

The Postgres credentials live inside `local-k8s-deps-values.yaml` and
are mirrored in `local-k8s-values.yaml` so the server can connect. They
are demo-only. Rotate by changing BOTH files.

## Key Files

- `local-k8s-deps-values.yaml` -- Dependencies chart values
- `local-k8s-values.yaml` -- Server chart values
- `scripts/setup-rsa-keys.sh` -- Generates the JWT keypair Secret
- `scripts/start.sh` -- helm repo add + JWT keys + install both charts
  + CoreDNS NodeHosts
- `scripts/stop.sh` -- Uninstall + PVC cleanup + namespace delete +
  CoreDNS cleanup
- `.env.example` -- Future per-deployment secrets (not yet wired)
